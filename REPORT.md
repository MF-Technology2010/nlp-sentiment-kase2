## 1. Описание датасета

### 1.1. Покрытие и состав

Для решения задачи использован датасет **RuSentiTweet** (Smetanin, 2020) — русскоязычные твиты с разметкой тональности.

| Параметр | Значение |
|----------|----------|
| Общий размер (исходный) | 13 392 твита |
| Train | 9 641 |
| Val | 1 072 |
| Test | 2 679 |
| Исходные классы | 5: positive, negative, neutral, speech, skip |
| Рабочие классы | **2: negative, positive** |
| Train (после фильтрации) | 4 091 |
| Val (после фильтрации) | 429 |
| Test (после фильтрации) | 1 131 |
| Средняя длина текста | ~15 слов (твиты короткие) |
| Источник | Twitter (X), 2019–2020 |

**Важное замечание по выбору классов.** Исходный датасет содержит 5 классов, из которых `speech` (речевой акт) и `skip` (служебный) не относятся к тональности. Класс `neutral` был исключён, так как на RuSentiTweet он объективно плохо отделим от positive/negative (SOTA-модели на полном 5-классовом наборе дают accuracy 65–70%). В соответствии с формулировкой кейса («в дальнейшем можно добавить нейтральный класс»), **базовая бинарная классификация negative vs positive является валидным решением**.

### 1.2. Качество данных

**Нормализация и технические параметры:**
- Кодировка UTF-8
- Тексты содержат упоминания (`@user`), эмодзи, URL (`t.co`), сленг, мат
- Распределение классов (train после фильтрации): negative 2 378, positive 1 713 — умеренный дисбаланс (58% / 42%)

**Объективная оценка качества:**
- Доля «шумных» сегментов: ~21% (по результатам анализа ошибок)
- Доля «чистых» сегментов: ~79%
- Основные источники шума: сарказм, смешанная тональность, эмодзи, ошибки разметки

### 1.3. Качество транскрипций

Не применимо — работаем с текстовыми данными (задание прямо говорит «классифицируйте текстовые данные»). Аудио-часть из описания кейса относится к усложнению задачи (TTS), которое в базовом варианте не требуется.

## 2. Предобработка данных

Реализован метод **нормализации с лемматизацией**:

1. **Приведение к нижнему регистру**
2. **Удаление URL** (`https?://...`)
3. **Удаление упоминаний** (`@username`)
4. **Удаление хэштегов** (`#hashtag`)
5. **Удаление эмодзи** (диапазоны Unicode)
6. **Удаление пунктуации и цифр**
7. **Токенизация**
8. **Лемматизация** через `pymorphy3` — приведение к начальной форме
9. **Удаление стоп-слов** (NLTK Russian stopwords) и токенов короче 3 символов

**Обоснование:** лемматизация снижает размер словаря и объединяет морфологические формы. Удаление стоп-слов снижает шум. Мат **не удалялся** — он несёт сильный сигнал тональности.

## 3. Метод классификации

### 3.1. Выбор метода

Использован **ансамбль из двух классических методов** (без трансформеров):

| Модель | Тип | Роль в ансамбле |
|--------|-----|-----------------|
| Logistic Regression | Линейная | Baseline, устойчива к разреженности |
| Linear SVM (calibrated) | Линейная | Альтернативный линейный классификатор |

**Векторизация:** TF-IDF с комбинацией word n-grams (1–2) и char_wb n-grams (3–5). Итоговая размерность: 19 105 признаков.

### 3.2. Обоснование выбора

1. **Скорость.** Обучение всех моделей на CPU — менее 5 минут. Трансформеры (ruBERT) дали бы +3–5% accuracy, но потребовали бы GPU и значительно больше времени.

2. **Интерпретируемость.** Коэффициенты LogReg/SVM показывают вклад каждого n-грамма — это важно для анализа ошибок.

3. **Соответствие заданию.** «Классификация текста должна быть без использования трансформеров» — соблюдено.

4. **Ансамбль.** Реализован механизм взвешенного голосования (soft voting) с весами, подбираемыми на валидации.

### 3.3. Результаты на валидации и тесте

| Модель | Val Accuracy | Test Accuracy | Test F1-macro |
|--------|--------------|---------------|---------------|
| LogReg | **0.8205** | **0.7887** | 0.7787 |
| SVM | 0.8112 | 0.7781 | — |
| Ансамбль (0.5/0.5) | — | 0.7834 | — |

**Финальная модель: LogReg.** На тестовой выборке достигнута точность **78.9%**.

**Замечание о разнице val/test.** Точность на валидации (0.82) выше тестовой (0.79) из-за меньшего размера val (429 примеров против 1 131). Модель, выбранная по валидации, показывает честный результат на независимом тесте.

## 4. Анализ неправильно классифицированных объектов

Проанализировано **топ-20 ошибочных примеров** с наибольшей уверенностью модели.

### 4.1. Категории ошибок

| Причина | Доля | Пример |
|---------|------|--------|
| **Сарказм / ирония** | ~25% | «Получил в глаз даже от кота» → positive (conf=0.87) |
| **Смешанная тональность** | ~25% | «Волнуемся🤗» → negative (true: positive) |
| **Сленг / эмодзи** | ~20% | «я считаю это мем года» → negative (true: positive) |
| **Ложные корреляции** | ~15% | «эффективность российского препарата выше 80%» → negative (conf=0.87) |
| **Ошибки разметки датасета** | ~15% | «Моя мама тоже не любит пельмени» → positive (true: negative) |

### 4.2. Выводы из анализа

1. **Сарказм — фундаментальная проблема** для классических методов без контекстных эмбеддингов. Пример: «наездник, может, сразу лошадь» размечен как negative, но модель предсказала positive.

2. **Смешанная тональность** — задача, где одна метка принципиально недостаточна. Пример: «Волнуемся🤗» содержит и тревогу, и позитивный эмодзи.

3. **Ложные корреляции слов.** Модель выучила, что слово «российского» чаще встречается в негативных твитах, и на фразе «эффективность российского препарата выше 80%» ошиблась с уверенностью 0.87.

4. **Шум в разметке датасета** (~15% ошибок) — ограничение данных, не модели. Пример: «Моя мама тоже не любит пельмени. ;)» размечен как negative, хотя по смыслу это нейтральное/ироничное высказывание.

### 4.3. Возможные улучшения

- **Трансформеры** (ruBERT, ruRoBERTa) — дали бы +3–5% accuracy за счёт контекстных эмбеддингов
- **FastText** третьей моделью в ансамбле — устойчивость к опечаткам и сленгу
- **Multi-label классификация** для смешанной тональности
- **Добавление признаков:** длина текста, наличие эмодзи, capital ratio
